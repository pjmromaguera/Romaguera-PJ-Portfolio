From a local storm-track file to a tested BigQuery pipeline

Historical tropical-storm track data (IBTrACS) starts out as a single local netCDF file. Turning it into something queryable and trustworthy meant building a real cloud pipeline around it — not just loading it once and calling it done.

Objective

  • Quantify historical tropical-storm exposure along Vietnam's coastline using IBTrACS.
  • Build a reproducible, testable cloud pipeline rather than a one-off local script.
  • Lay the groundwork to eventually cross-reference storm exposure against mapped mangrove extent from the VM0033 project, to surface high-exposure, low-buffer coastal segments.

Approach

  • Load the local IBTrACS historical storm-track netCDF file into a dedicated GCP project (mangrove-storm-risk).
  • Create and populate BigQuery datasets entirely through the gcloud/bq CLI, for a reproducible, scriptable setup rather than manual console clicks.
  • Build dbt models on top of the raw loaded data, and run dbt tests to catch data-quality issues before they propagate downstream.

Tools

  • Google Cloud Platform / BigQuery for cloud-based storage and querying.
  • gcloud / bq CLI for project and dataset management.
  • dbt for transformation modeling and automated data-quality testing.

My Role

  • Designed and built the pipeline end to end, from the raw IBTrACS file to tested BigQuery tables.
  • Managed the GCP project and BigQuery datasets via CLI rather than the console, for reproducibility.
  • Wrote and ran dbt tests as part of the build, not as an afterthought.

Key Takeaways

  • Historical storm-track data is messier than it looks going in — raw track points needed real staging before they were usable for any coastline-level aggregation.
  • Writing dbt tests as part of the build, rather than checking data quality after the fact, made the BigQuery output something I could actually trust downstream.
  • This pipeline is a foundation, not a finished risk score: the next step is joining it against mapped mangrove extent from the VM0033 screen to identify specific high-exposure, low-buffer coastal segments.

Pipeline Notice

This project uses IBTrACS historical storm-track data — not a live feed — and reflects a self-directed data-engineering exercise built alongside my VM0033 mangrove-restoration work. It demonstrates the BigQuery/dbt pipeline itself; it does not yet publish a finished storm-risk score or interactive map. No AWS services were used in this build.
